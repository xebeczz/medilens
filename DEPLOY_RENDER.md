# MediLens AI — Deploy to Render (free tier)

## Why localhost failed
`GET http://localhost:5173/ net::ERR_CONNECTION_REFUSED` means nothing was
listening on port 5173 on that laptop — the Vite dev server was not running.
It is not a bug in the app. Deploying to Render removes the localhost
dependency entirely: open the live URL in Chrome from any machine.

## Steps still needed (browser — cannot be done from the VM alone)
1. **Create the GitHub repo** `xebeczz/medilens-ai` in the browser
   (the GitHub App cannot create repos — 403; repo does not exist yet,
   checked 2026-11-24: `GET /repos/xebeczz/medilens-ai` → 404).
   Create it empty (no README/.gitignore — the local repo already has them).
2. **Push the local repo** (already committed locally, branch `main`):
   ```
   git remote add origin https://github.com/xebeczz/medilens-ai.git
   git push -u origin main
   ```
   If the push is 403, the GitHub App access does not include this repo yet:
   GitHub App settings → "Only select repositories" → tick `medilens-ai`
   (keep the others ticked) → Save → retry the push.
3. **Render → New → Blueprint** → connect `xebeczz/medilens-ai` → Apply.
   Render creates both services from `render.yaml`. `MEDILENS_SECRET_KEY`
   is generated by Render (`generateValue: true`).
4. Wait for both deploys to report complete, then wake the free instances
   (first load after sleep takes ~50s) and verify:
   - Frontend loads (HTTP 200) at https://medilens-ai.onrender.com
   - `GET https://medilens-ai-api.onrender.com/api/health` returns `{"status":"ok"}`
   - Demo login works, and uploading `samples/sample-medical-report-cbc.pdf`
     extracts Hb 14.4 Within / Platelet 138 Below / Glucose 104 Above.

## Free-tier data warning (tell the user plainly)
Render's disk is ephemeral: the SQLite database (`medilens.db`) and
`backend/uploads/` are WIPED on every restart/redeploy. Accounts and uploaded
reports do NOT survive. Recovery is one step: log in with the demo account
(demo@medilens.ai / demo1234) — the frontend auto-registers it on first login
if it does not exist — then re-upload the sample report. Registered accounts
made on the live site are lost on restart the same way.
